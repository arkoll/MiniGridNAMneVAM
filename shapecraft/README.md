# ShapeCraft: гипотеза о правилах по форме, независимых от цвета

Код к отдельной гипотезе на среде `XLand-MiniGrid-ShapeCraft-Easy-8x8-v1`.
Ветка самостоятельная и в `main` не вливается: здесь только то, что относится к этой линии
экспериментов.

Чекпоинтов и датасетов тут нет — они остаются на сервере (`runs/` около 70 ГБ,
`data/` около 27 ГБ). Всё воспроизводится скриптами из `scripts/`.

## Что за гипотеза

Правила крафта заданы **формами** и не зависят от цвета. Обучающие и валидационные задачи
разведены по комплементарной привязке цвета к форме: если модель выучила правило как
«шар плюс куб», она обязана перенестись на палитру, где те же формы окрашены иначе.

Проверка — доля решённых задач в замкнутом контуре через настоящую среду, на двух банках:

- **val_id** — обучающие задачи, но невиданные раскладки и сиды (21 млн);
- **val_ood** — валидационные задачи, комплементарные привязки цвета (22 млн).

## Главные результаты

Разрыва между `val_id` и `val_ood` нет ни у одного из четырёх способов собрать данные —
`results/final_T1.png`. Максимальное расхождение 0.034 при стандартной ошибке 0.03.

Отдельно важное методическое наблюдение: **жадная раскатка (argmax) обесценивает любую
реактивную политику в этой среде**. Один и тот же чекпоинт даёт 0.465 при argmax и 0.905 при
сэмплировании, и даже привилегированная политика PPO теряет на жадности 0.155 (0.845 против
1.000). Все проигранные эпизоды упираются ровно в лимит шагов — политика без памяти
зацикливается. Развёртки по температуре: `results/temp_success_rate*.png`.


## Как применить патч

```bash
cd repos/nano-world-model
git apply ../../shapecraft/patches/nanowm_shapecraft.patch
```

Патч добавляет:

- `src/callbacks_shapecraft.py` — метрики действий отдельно по `val_id` и `val_ood`
  (делит валидацию по префиксу имени файла);
- конфиги датасетов `src/configs/dataset/xland/*.yaml` и эксперимента
  `src/configs/experiment/xland_joint_ours.yaml`;
- в `src/wm_datasets/data_source/xland.py` — переменную окружения `XLAND_ACTION_FIELD`,
  чтобы читать как целевое действие либо экспертную метку, либо фактически выполненное
  действие, не переписывая десятки тысяч файлов;
- в `src/callbacks.py` — починку `CUDACallback`: при возобновлении с чекпоинта Lightning
  восстанавливается в середину эпохи и вызывает конец эпохи без её начала, из-за чего
  падал замер времени.

## Основные скрипты

| файл | что делает |
|---|---|
| `dagger_rollout.py` | раскатка эпизодов: экспертная или случайная политика, метка действия всегда экспертная |
| `dagger_write.py` | рендер в 128 и запись npz; `--slice-frames` режет случайные эпизоды на отрезки |
| `build_final_views.py` | представления датасета символьными ссылками, поровну по задачам |
| `run_final_pipeline.sh` | итоговое сравнение четырёх составов данных целиком |
| `eval_closed_loop.py` | сторона среды в замкнутом контуре |
| `run_closed_loop.sh` | поднимает сервер действий и гоняет контур |
| `expert_reference_sr.py` | эталон политики PPO на тех же банках и сидах |
| `entropy_states.py`, `entropy_measure.py` | энтропия головы действий с разбором по классам задач |
| `split_by_tree.py` | разбор побед по тому, выводится ли правило из кадра |
| `plot_style.py`, `plot_all_styled.py` | графики в едином стиле |

Пути в скриптах привязаны к серверу школы (`/home/user8_2/AIRI_WAM`), при переносе их
нужно поправить.
